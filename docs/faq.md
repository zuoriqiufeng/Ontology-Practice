# FAQ

## Q1：为什么不把错误码写进本体？  
码空间随外部世界线性增长（产品自身数百、加上各数据库上万）。任何一层穷举都是把无穷搬家。
**码只作入口**：入口归一 → 语义类别（有界）→ 边推理 → Skill/日志。码表在 Tool 层侧车，不进本体。

## Q2：BKN 和 Skill 的分界线在哪？  
能做决定的是**结构**（谁依赖谁、会牵连谁）→ 写本体；会随版本/环境变的是**事实**（端口、码、阈值）→ 写值数据/Skill。

## Q3：没有 Qdrant / 嵌入模型能跑吗？  
能。检索退化为关键词/BM25；基于本体边的工具（`resolve_relation`、`diagnose_*`）不受影响。

## Q4：版本号怎么定？  
工具用 SemVer；**本体版本 = 文件清单的哈希**（内容一变版本必变），记录在 `bkn-version.json`。

## Q5：为什么改本体要走「候选」？  
优化产物不就地生效：候选目录 + 审批 + 门禁 + 可回滚。见 `spec/05-governance.md`。

## Q6：为什么不把别名都写成一张大表？  
别名只收「不可生成」的等价说法（数据文件、带 provenance）；码的机械变体由形态解析生成；长尾说法走检索兜底，不猜。

## Q7：可以只用 spec 不用运行时吗？  
可以。`spec/` 是独立可读的规范；运行时只是它的参考实现。
