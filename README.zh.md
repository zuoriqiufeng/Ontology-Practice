# Ontology-Practice（BKN 本体工程实践套件）

**BKN（Business Knowledge Network，业务知识网络）** 是给 Agent 用的领域知识层：
用「类 · 边 · 实例登记」描述一个产品的世界模型，让 Agent 先「想对」再「动手」。

本仓提供三样东西：

| 组成 | 内容 |
|---|---|
| **SPEC**（规范） | 为什么这么设计、本体模型、`.bkn` 格式、图推理语义、治理模型、BKN 与 Skill 的边界 |
| **运行时**（可跑） | `plugin/`：BKN 解析、13 个 Tool、图遍历推理、混合检索（可降级）、可观测 |
| **治理工具链** | `scripts/`：lint、版本与变更集、候选/待审、回滚演练、日志统计、回放门禁 |

## 快速开始

```bash
pip install -e .
bkn-lint --error-only bkn/        # 校验本体骨架
```

完整上手（写第一个本体、接入 Agent）见 `docs/`。

## 与 OpenBKN Engineering 的区别

本项目的**理念原型是爱数（AISHU）的 BKN 本体理论**（「BKN 给思路，Skill 给做法」、值委托、四元终态）。
我们受它启发，但做的是**另一件事：面向产品运维的本体工程**。

| 维度 | OpenBKN Engineering | Ontology-Practice（本项目） |
|---|---|---|
| 定位 | BKN 的**方法论 ＋ 技能集**（需求 → PRD → 本体构建 → 发布的工作流） | **产品运维**的本体工程：把运维知识做成可运行、可机检的闭环 |
| 交付物 | Skills / 模板 / 工作流 | 规范（`spec/`）＋ 运行时可跑（`plugin/`）＋ 治理工具链（`scripts/`：lint/门禁/候选/版本/回滚/可观测）＋ 示例本体 |
| 验证方式 | 以流程与文档评审为主 | **机检五道门禁**：结构 lint、回归测试、结构量、置信度/体积基线、案例回放 |
| 场景 | 通用建模与交付协作 | 运维排障/诊断：进程拓扑、检查维度、机制候选、取证路径 |
| 关系 | 同一理论谱系的另一种实践 | 两者**互补不替代**；本项目**未复制其源码** |

> 我们不追求「通用方法论全覆盖」，只服务一个目标：**让产品的运维知识可运行、可验证、可演进**。
