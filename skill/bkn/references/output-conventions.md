> **权威地位**：本件是「Skill 与 Agent **面向人**输出时怎么组织信息」的**执行期权威件**；
>   仓库侧原件 `原 doc/update/skill-output-conventions.md（2026-10-15 清理）` 自 2026-10-15 起降为**依据与留档**（对照驱动 G-14 的来源记录）。
> **全仓规则层落点**：`AGENT.md` R-3 是同一规范的 **5 条摘要**，适用于**所有** agent / skill 的对外输出；本件是它的**详解 ＋ 自检清单**。
> **适用对象**：本 Skill 与其 `references/**`，以及**所有 skill 面向用户的输出**（**不**约束 Tool 返回结构——那是 `plugin/schemas.py` 的事）。
> **引用纪律**：遵循 `AGENT.md` R-1，本件**不写跨文档 markdown 链接**，引用一律纯文本路径 / 编号。

## 1. 五条规范

| # | 规范 | 为什么 |
|---|---|---|
| 1 | **摘要优先**：默认只给「结论 ＋ 关键数字 ＋ 下一步」，明细按需展开；**不把过程当结果** | 现场看的是判断，不是原始数据堆 |
| 2 | **一轮一种主格式**：同一轮里表格 / 列表 / 代码块**择一为主**，不混排堆砌 | 混排会让人找不到重点 |
| 3 | **内部码转中文**：面向用户时不直接抛内部枚举（如 `dimension:log_readable`），**先中文后原文**；复用既有别名侧车（`plugin/constants.py` 的 `DIMENSION_ALIASES` / `SYMPTOM_ALIASES` / `ERROR_ALIASES`），**不另建一套词典** | 复用侧车（D5）；原文仍留，排查要用 |
| 4 | **禁 emoji**：正式回执与文档不用 emoji **装饰** | 现场终端 / 日志 / 工单系统渲染不可控 |
| 5 | **详情按需**：用户说「看详情 / 展开」才给完整中间产物；**长清单只给头部若干条，全文落文件** | 与规范 1 是一体两面 |

## 3. 自检清单（写 / 改 Skill 时逐条过）

- [ ] 默认输出是**摘要**（结论 ＋ 关键数字 ＋ 下一步），不是全量明细？
- [ ] 同一轮只用了**一种**主格式？
- [ ] 面向用户的文本里**没有**未翻译的内部枚举？（有的话用别名侧车的中文名，**并保留原文于括号**）
- [ ] 没有 emoji **装饰**？（`✅` / `⚠️` 这类承载状态语义的功能符号可用）
- [ ] 明细是**按需**展开的？长清单是否只给了头部若干条并把全文落到文件？

## 4. 三个易误读处（实测踩过）

1. **「禁 emoji」不禁止功能符号**：`✅` / `⚠️` / `❌` 承载状态语义，可用；装饰性表情不用。
2. **「内部码转中文」是「先中文后原文」**，不是删掉原文：`日志可读性`（`dimension:log_readable`）——排查时仍需原文可搜。
3. **「摘要优先」不等于「不给细节」**：细节按需展开，且默认轮次里应给「下一步」，否则读者不知道要不要继续问。
