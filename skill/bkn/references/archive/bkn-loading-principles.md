# BKN 按需加载原则

> 2026-06-23 | 从强制加载到按需参考的设计修正

## 核心原则

**BKN 是查漏补缺的参考，不是每次操作的必选项。**

## 四象限判断法

```
                              查 BKN
                                 │
          ┌──────────────────────┼──────────────────────┐
          │                      │                      │
     遇到错误码             遇到不熟悉的          写操作(改/删/
     -4073等               数据库/术语           重启/停止)
          │                      │                      │
     risks.bkn              database.bkn           shared/risks.bkn
     (诊断链路)              (源端要求)              (禁止项)
─────────────────────────────────┼───────────────────────────────
                              不查 BKN
                                 │
          ┌──────────────────────┼──────────────────────┐
          │                      │                      │
     只读查询                 熟悉操作              Skill已覆盖
     (list/query)           (重复执行过的)         (内建知识)
```

## 信号驱动规则

| 信号 | 动作 |
|------|------|
| 有 error_code | **必查** → risks.bkn |
| 是写操作 | **先查** → shared/risks.bkn |
| 不熟悉 DB 类型 | **查** → database.bkn |
| 端口/权限/字符集 | **查** → env_matrix.bkn |
| 只读查询 | **不查** |
| 无报错 + Skill 已覆盖 | **不查** |

## 反模式

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 把 BKN 放进 Persona SOUL.md | 每次请求 +2000 token | Persona 只放人格/执行规则 |
| 每次操作强制加载 BKN | 每轮 +2-3 次 read_file | 按需 search_files |
| 全量合并所有对象 | 查节点带入 SyncRule | 一个对象一个文件 |
| 操作约束和知识诊断混放 | 排查异常时加载无关约束 | 两类 BKN 分工 |

## 与 KWeaver 的差距

KWeaver 的 BKN 通过 ContextLoader 自动按意图注入 Schema，不需要 Agent 判断。Hermes 无此基础设施，Agent 需手动调用 `find_bkn.py` 做路由。

保持信号驱动、工具层路由、按需加载——这是 Hermes 框架内的最优实践。
