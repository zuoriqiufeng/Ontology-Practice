# BKN 查询模式

> 2026-06-23 | 从 Demo Product BKN 实践总结

## 核心规则

**报错必查，写入先查，不懂就查，熟悉跳过。**

## 四象限决策

```
                              需要BKN
                                 │
         遇到错误码         遇到不熟悉的        写操作(改/删/
         -4073等           数据库/术语         重启/停止)
              │                  │                  │
              ▼                  ▼                  ▼
         查知识型BKN         查知识型BKN        查操作型BKN
         risks.bkn          database.bkn       shared/risks.bkn
         (诊断链路)          (源端要求)          (禁止项)

─────────────────────────────────────────────────────────────

                              不查BKN
                                 │
         只读查询             熟悉操作             不确定但
        (list/query)        (重复执行过的)        Skill已覆盖
              │                  │                  │
              ▼                  ▼                  ▼
         直接执行             直接执行             直接执行
```

## 决策规则

查 BKN 的条件（满足任一即查）：
- 报错了，且有 error_code（-4073 / -4016 / -4071 / -4031 / -4046）
- 操作涉及不熟悉的数据库类型（DM / OB / MSSQL 三种模式）
- 写操作（create / start / stop / delete / restart / modify）
- 操作失败重试前，不确定根因
- 用户问"怎么配"/"有什么区别"/"为什么不行"
- Skill SKILL.md 中没有覆盖到的信息

不查 BKN 的条件（全部满足才跳过）：
- 只读查询（--list / --info / 查看状态）
- 没报错（正常操作流程中）
- Skill 内建信息已覆盖（状态机、命令路径、基本约束）
- 之前成功执行过的同类操作，没变化

## 查 BKN 的工具选择

```
用户问题
    │
    ├── 知道关键词 (错误码/术语/DB名)
    │       └── search_files  ← 最省, 1次调用, ~5行
    │
    ├── 不知道关键词，但知道类别 (要看全部约束/全部DB差异)
    │       └── read_file     ← 1次调用, ~40-200行
    │
    └── 以上都不满足，需要语义检索
            └── Qdrant        ← 向量检索, 人工筛选
```

## 两类 BKN：操作型 vs 知识型

| 维度 | 操作型 BKN | 知识型 BKN |
|------|-----------|-----------|
| 位置 | Skill bkn/ 目录 (通过软链接共享) | ~/.hermes/demo-product/bkn/ 或独立目录 |
| 内容 | 命令/约束/状态机 | 诊断/原理/差异 |
| 触发 | 执行操作前 | 排查异常/对比差异时 |
| risks | "禁止做什么" (16条约束) | "出错怎么办" (8条诊断+Qdrant链路) |
| database | 基础类型+端口 (7行) | 10种DB源端要求+增量机理 (198行) |
| 生成来源 | Skill 定义 + 运维经验 | 产品文档 + 配置手册 |

两者互补，不合并。操作型文件轻量精准，知识型文件深入全面。

## network.bkn — 路由入口（可选）

network.bkn 已从纯索引进化为 **索引 + 路由表**：

| 段 | 内容 |
|---|------|
| §路由表 | 10级优先级: 信号正则 → BKN文件映射 |
| §Object索引 | 对象→文件，含知识型BKN引用 |
| §Action索引 | 动作→文件 |
| §Risk索引 | 约束+错误码 |
| §文件清单 | 操作型+知识型+纯知识全貌 |
| §决策流程 | 信号→路由→search_files/read_file→Qdrant |

**使用方式**：不确定查哪个 BKN 时，`search_files(network.bkn, pattern="路由表")` 获取路由规则。正常操作不读。

对比之前的"弃用"状态：弃用是针对纯索引功能（被 SKILL.md 文件索引替代）。路由表功能是新增的，用于 Agent 首次不确定文件定位。
