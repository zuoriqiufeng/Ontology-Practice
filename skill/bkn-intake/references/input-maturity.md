## 1. 成熟度分级（先定位，再决定做不做）

| 级 | 名字 | 判据（满足才算） | 允许的动作 |
|---|---|---|---|
| **M0** | 想法 | 只有方向 / 单句诉求，无材料 | **只输出澄清问题**；不建模、不建候选 |
| **M1** | 素材 | 有材料（文档 / 手册 / 日志 / 复盘），但**未区分事实与假设** | 先做**材料登记**（来源、章节、可定位锚点） |
| **M2** | 可建模 | 材料能支撑「对象 / 关系 / 动作」三类候选的**至少一类**，且每条候选**能指到出处** | 进入建模（skill/bkn 或 skill/bkn-updater）；候选须过准入四关 |
| **M3** | 可评审 | 候选齐、**确认状态已分层**、验收判据可写 | 走 24 号 §2.3 评审 → 候选流程（doc/optimize/pending/） |

> **降级纪律**：任何一条候选**指不到出处** ⇒ 该条降回 M1（登记为「待取证」），**不得**为了凑齐而写成已确认。

## 2. 材料登记（M1 起必做）

| 材料 | 类型 | 位置（可定位到章节/页） | 用途 | 已用 / 未用 |
|---|---|---|---|---|
| （示例）doc/projectdoc/Demo Product技术白皮书_9.1.5 26S3.docx | 产品原理 | 4.5 拓扑结构 | 机制判据的第二来源 | 已用 |
|  |  |  |  |  |

**规则**：① 只登记**可定位**的锚点（章节号 / 页码 / 行号 / 时间戳）；② 未用的材料也要列（避免「以为没材料」）；③ 外部件（仓外路径）写绝对路径。

## 3. 待确认问题清单（**不确认就不建模**）

| # | 问题 | 问谁 | 不确认的风险 | 建议问法 | 状态 |
|---|---|---|---|---|---|
| Q1 | （示例）该状态码的官方含义与现场口语是否一致？ | 产品 / 现场 | 别名写错 ⇒ 路由到错误维度 | 「现场说的 X 和官方表的 Y 是同一个吗？」 | 待确认 |

**规则**：① 一条问题一个主题；② 必须写「不确认的风险」——没有风险的可以直接不问；③ **状态列只允许三值**：已确认 / 待确认 / 待裁定（后者指需用户裁断的设计选择）。

## 4. 建模清单（M2 起；候选三分类）

| 类别 | 候选 | 出处 | 确认状态 | 过了准入四关？ |
|---|---|---|---|---|
| 对象候选 |  |  | 候选 | — |
| 关系候选 |  |  | 候选 | — |
| 动作候选 |  |  | 候选 | — |

**纪律（硬）**：

1. **候选 ≠ 已确认**：上表默认全部是「候选」；只有拿到出处 ＋ 业务确认才可改状态。
2. **值数据不进本表**：别名、阈值、码表、公式先判「是不是值数据」（24 号 §2.5），是则直接下沉侧车，**不列为候选**。
3. **过四关才落盘**：本表通过后，按 24 号 §2.3 出**全范围论证文档**，再走候选流程。

## 5. 出口

| 成熟度 | 出口 |
|---|---|
| M0 | 澄清问题清单（本件 §3） |
| M1 | 材料登记表（§2）＋ 待确认清单（§3） |
| M2 | ＋ 建模清单（§4）→ 交给 skill/bkn / skill/bkn-updater |
| M3 | ＋ 论证文档 → doc/optimize/pending/C-*/（**apply 须人工记名**） |
