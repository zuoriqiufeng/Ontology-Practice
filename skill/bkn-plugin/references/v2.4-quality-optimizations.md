# v2.4 质量评估精度提升 + 工程健壮性修复

> 2026-07-03 实施。在 v2.3 四象限降权框架上解决四个设计局限和若干运行时 bug。

## 优化

### 1. gap_coverage 精准语义匹配

`_gap_coverage_enhanced()` 替代 `_extract_gap_keywords` 泛词匹配。用正则模式检测 hit 内容中是否出现 gap 真正关心的实体：

```python
ENTITY_PATTERNS = {
    "版本": re.compile(r"版本.*?(?:\d+\.\d+|限制|要求)"),
    "数据类型": re.compile(r"数据.*类型.*映射|类型.*转换|varchar2|number\("),
    "权限": re.compile(r"grant\b|权限|授权|privilege", re.IGNORECASE),
    "配置": re.compile(r"binlog|归档|archive.log|redo|server.id|参数"),
    "错误码": re.compile(r"-\d{4}"),
    "风险": re.compile(r"风险|异常|故障.*原因|error|失败|超时"),
    "跨地域": re.compile(r"跨地域|异地|远程|网络.*延迟|带宽|压缩"),
    "前置条件": re.compile(r"前置|准备|要求|checklist|配置要求|环境要求"),
}
```

信号从"风险/异常/处理"泛词命中 → "gap 说缺版本限制 → 检查 hits 里有没有版本号模式"的精准匹配。

### 2. 维度标签化

`_decompose_queries` 返回值从 `list[str]` 改为 `list[tuple[str, str]]`（维度名, 查询文本）。检索循环中给每个 hit 打 `_dim` 标签，`assess_qdrant_quality` 直接取标签做精确比对，不再需要子串猜测。

### 3. 噪声列表动态推导

新增 `constants.py` 统一维护 `KNOWN_DBS` (18项) + `DB_ALIASES` (8项) + `DB_NOISE_VARIANTS`。`_build_noise_patterns(source, target)` 根据当前查询动态排除相关 DB，使用模糊匹配（`db_lower in rel or rel in db_lower`）处理 "Oracle 19c" 这类带版本号的名字。

`resolver.py` 的 `check_compatibility` 也从独立内联列表改为 import `KNOWN_DBS`，一处维护两处生效。

### 4. design_solution 返回补齐 + Schema 收敛

新增 `_extract_from_relations()` 从 expanded relations 提取 `prerequisite/constrains/risks_of` 到顶层字段。Schema description 同步收敛。

## 别名系统

`normalize_db()` 支持分词+整体双重匹配：
- "DM" → ["DM", "达梦"]
- "达梦 DM" → ["达梦 DM", "达梦"]（分词匹配）
- "OB 4.2" → ["OB 4.2", "OceanBase"]

`is_db_match()` 封装兼容性检查。
