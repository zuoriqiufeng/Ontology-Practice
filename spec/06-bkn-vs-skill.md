# 06 · 边界：BKN 给思路，Skill 给做法

## 三层职责

| 层 | 回答 | 不回答 | 变化频率 |
|---|---|---|---|
| **BKN 本体** | 有什么、能做什么、有什么约束、谁和谁连着 | 命令、参数、阈值、现场状态 | 稳定（语义） |
| **Plugin 运行时** | 怎么高效查出来 | 不生产知识，只路由与求值 | 随结构变 |
| **Skill** | 具体怎么操作（命令/脚本/校验） | 不定义语义，只消费指针 | 随环境/版本变 |

## 三条判据

1. 能做决定的是**结构**（谁依赖谁、会牵连谁）→ 写本体；
2. 会随版本/环境变的是**事实**（端口、码、阈值）→ 写值数据/Skill；
3. 会随时间变的是**实例状态** → 不进本体（ABox），要有外部源。

## 值委托（指针）

本体只写「去哪找」：

```
对象: database
  版本下限 → 由 skill:<产品>-db-manager 提供
```

运行时把指针原样返回；Agent 据此加载对应 Skill。**本体永不返回可执行命令串。**

## 产品事实委托（多产品复用）

通用方法（格式/准入/推理/审计）与方法学 Skill 产品无关；产品的库/端口/命令/案例由**该产品自己的 Skill** 承载。
通用 Skill 里用占位符互指（如 `{db_manager_skill}`），并维护一张「占位符 → 当前产品 Skill」对照表；新产品接入时**重新登记**，不沿用旧产品的事实。
